# Angel Swert - Mapping Discovery to Website (Stage 1)

## What this file from client actually is
Source file is a qualification questionnaire template (diagnostic form), not final marketing copy.

That means:
- It defines what must be clarified before launch
- It does not contain ready service descriptions, pricing copy, case texts or final CTA wording

## What we can use it for immediately
We can build a strict content architecture so each page has the right business purpose and required data inputs.

## Mapping: Discovery Sections -> Website Blocks

### Home page
Use data from sections:
- 2 (Objectives/KPIs): core promise and main CTA
- 4 (Audience): "for whom" block
- 5 (Conversion path): CTA destination and lead route
- 6 (Website/funnel readiness): trust and clarity block

Recommended home blocks:
1. Hero (one main outcome + one CTA)
2. For whom this is
3. Services preview
4. Program/package preview
5. YouTube channels block (4 links)
6. Trust proof (cases/testimonials)
7. Final CTA

### About page
Use data from sections:
- 1 (Company/offer/decision context)
- 4 (markets/languages context)
- 11 (rights/ethics stance, if relevant)

Recommended about blocks:
1. Brand story
2. Method and principles
3. Why this approach is reliable
4. CTA

### Services page
Use data from sections:
- 3 (channel and production maturity)
- 7 (automation scope)
- 8 (AI-agent roles, if presented as service capability)

Recommended services blocks:
1. Service categories
2. What is included / excluded
3. Workflow and approval model
4. FAQ
5. CTA

### Programs page
Use data from sections:
- Package Selection Logic (STARTER/GROWTH/PRO)
- Additional Growth Layer
- 13 (pilot structure and decision)

Recommended programs blocks:
1. Package cards: Starter / Growth / Pro
2. Feature comparison (volume, channels, languages, publishing, automation)
3. Add-on Growth Layer
4. Pilot-first option block
5. CTA

### Contact page
Use data from sections:
- 5 (lead follow-up owner and response time)
- 10 (approval speed and decision-maker)

Recommended contact blocks:
1. Contact channels
2. Expected response SLA
3. Qualification mini-form
4. Consent/processing note

### Blog page
Use data from sections:
- 3 (what content already works)
- 4 (audience problems/motivations)
- 5 (traffic goals)

Recommended blog logic:
1. Category clusters by audience problems
2. Each article includes service-relevant CTA
3. Internal links to services/programs/contact

## Critical data still missing for final page copy
Need client answers (not template) for:
- Exact service names and promised outcomes
- Program boundaries and commercial framing
- Real cases/testimonials and proof points
- Final CTA destination (book call, form, WhatsApp, etc.)
- Language strategy for public pages (EN/DE/RU)
- Contact ownership and response-time promise

## Immediate implementation plan (without waiting)
1. Rebuild all public pages by correct block order
2. Add package comparison section on Programs page
3. Keep copy as structured placeholders marked "to approve"
4. Prepare SEO-friendly blog structure and article template

## Fast content collection format to send client
Request one-page answer sheet with:
- Main offer in one sentence
- 3 audience segments
- 5 key pain points
- 3 transformations/results
- 3 flagship services
- Package positioning (Starter/Growth/Pro)
- Preferred CTA path
- 3 proof items (case/result/testimonial)
- Contact SLA
